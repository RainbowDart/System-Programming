# Практика № 1 — Исследование legacy-системы учёта оборудования

**Время:** 32 минуты. **Уровень:** продолжающие.

## Ситуация
Вы получили старое консольное приложение, которое используют для учёта оборудования отдела. Требуется разобраться в существующем коде, а не переписывать его с нуля.

## Задания
1. Запустите приложение и проследите путь данных: `Program` → `InventoryService` → `EquipmentRepository`.
2. Найдите и запишите **минимум три проблемы**. Для каждой укажите условие проявления, ожидаемое и фактическое поведение.
3. Исправьте **один** дефект, не меняя публичный контракт и корректные сценарии.
4. Добавьте или измените тест, который воспроизводит дефект до исправления и подтверждает исправление после.
5. Проверьте обычный сценарий и минимум один граничный сценарий.

## Ограничения
- Не переписывайте проект целиком.
- Не удаляйте существующие функции только потому, что они неудобны.
- Не используйте пустой `catch`.
- Не меняйте формат отчёта без необходимости.
- В отчёте о работе укажите, какие проблемы вы нашли, но не исправляли, и почему.

## Подсказки по исследованию
- Посмотрите, где нормализуется пользовательский ввод.
- Сравните название метода с тем, какие записи реально попадают в результат.
- Проверьте, как рассчитывается стоимость оборудования, купленного давно.
- Не считайте, что успешная компиляция означает корректное поведение.

- [ ] Найдены минимум три проблемы.
- [ ] Исправлен один дефект.
- [ ] Тест подтверждает исправление.
- [ ] Проверены два сценария.
